### 1. Channel 5 — MetFrag-lite fragmentation (`src/casmi/channels/fragmentation.py`)

In-silico fragmentation scoring: enumerate every fragment reachable by
breaking 1-2 acyclic bonds of a candidate SMILES (ring bonds don't
disconnect anything, handled naturally by the connected-components check),
compute each fragment's neutral mass (atom + attached-H mass, so no separate
H bookkeeping), then score how much of the observed spectrum's intensity is
explained by ion masses within tolerance (checking `+/-2` hydrogen shifts and
protonation/deprotonation per polarity). `fragmentation_scores()` takes the
best score across a molecule's spectra, matching Channels 1/2's aggregation
convention. Commit `7db8b65`. Tests: `tests/test_fragmentation.py` (18 tests).

### 2. Channel 4 wiring — FPNet into the pipeline (`src/casmi/pipeline.py`)

FPNet (`src/casmi/models/fpnet.py`) already existed and was trained
(session 3) but was never called by `pipeline.py`. Now: `predict_molecule`/
`run_pipeline` accept optional `fpnet_model`, `fpnet_config`, `fpnet_device`
params; when supplied, one forward pass per molecule produces fingerprint
logits, then `score_candidates()`/`normalised_score()` (already existed,
exact-Bayes dot product, one matmul) score every candidate. All torch imports
are function-local so the baseline stays import-clean of torch when FPNet is
omitted (`fpnet_model=None`), matching the existing "torch is optional"
pattern. Commit `adc8755`.

### 3. Learned GBM reranker (`src/casmi/channels/ranker.py`)

Replaces weighted fusion as an *option*. `assemble_features()` builds a fixed
22-column feature matrix per candidate (raw + rank-normalised + z-scored +
gap-to-best variants of library/analog/fragmentation/fpnet scores — see
`FEATURE_NAMES` in the module for the exact list, deliberately similar to the
reference notebook's 31-feature design but assembled fresh, not copied).
`train_ranker()` fits a bagged ensemble of `HistGradientBoostingClassifier`
over `RankerConfig.class1_priors x seeds` (2 priors x 4 seeds = 8 models by
default, matching the reference's own bagging design — this is credited with
eliminating a ~0.006 MRR seed-noise floor plus ~0.003 from prior-hedging in
the reference's own ablations). `Reranker.predict_proba()` averages
`predict_proba` across every ensemble member. `RankTrainingExample`/
`build_training_matrix()` group candidates by molecule so rank/z-score
features are relative to the right candidate set. Commit `6cded31`.

### 4. Pipeline refactor (`src/casmi/pipeline.py`)

Extracted `build_scored_candidates()` out of `predict_molecule()` — assembles
every channel's features for one molecule and returns the raw (unranked,
unfused) candidate list plus context (`library_hits`, `analogs`, raw
fragmentation/fpnet score arrays). Shared by `predict_molecule` (which
fuses/ranks) and the new `scripts/build_rank_train.py` (which needs the full
candidate list to attach training labels). Commit `10f66e2`.

### 6. Bug found and fixed: weighted fusion silently ignored Channels 4/5

**This was a real, non-obvious bug caught by checking Azure's actual output**,
not by code review. `DEFAULT_WEIGHTS` in `src/casmi/channels/fusion.py` only
had entries for `library_similarity`, `analog_power`, `analog_best_tanimoto`,
`analog_mean`, `mass_error_penalty` — never `fragmentation_score` or
`fpnet_score`. Since `fuse()` computes
`sum(weight * candidate.features.get(name, 0.0) for name, weight in w.items())`,
any feature absent from the weights dict is implicitly multiplied by zero.
Result: enabling `fragmentation_channel=True` changed diagnostics
(`best_fragmentation_score`) but had **zero effect on the actual ranking** —
stage 2 of the first validation run produced byte-identical MRR@25 to stage 1.

Fixed by adding `"fragmentation_score": 0.20, "fpnet_score": 0.05` to
`DEFAULT_WEIGHTS` (modest weights so mature evidence like library/analog
still dominates under plain weighted fusion; the *reranker* is what actually
learns optimal weights from data). Added 3 regression tests
(`test_fragmentation_score_has_nonzero_default_weight`,
`test_fpnet_score_has_nonzero_default_weight`,
`test_fuse_score_changes_with_fragmentation_feature`) that were verified to
fail against the pre-fix code and pass against the fix. Commit `7dd3a79`.

**Consequence**: the first Azure validation run (started 04:33 UTC) was
killed after ~28 minutes into stage 3 (cheap to discard — stages 1/2/3 would
otherwise have needed a full re-run) and restarted from scratch at 09:43 UTC
with the fix in place. This is the run currently in progress — see below.

Channel contribution unchanged across stages 1-3 (as expected — it's
computed from `best_library_similarity`, not the fused ranking):
library carries 26.75% of molecules, analog/other 73.25%. This confirms the
held-out split is honest (the leaky visible `test.parquet` gives 100%/0%).

**Key finding**: FPNet (Channel 4) is by far the largest single lift so far
(+0.13 overall MRR under plain weighted fusion), and it transforms class-2
(analog-only, no reference spectrum — the hardest reachable cohort) from
0.234 to 0.591 MRR. It also *reduces* class-1 MRR under weighted fusion
(0.908→0.787) — likely because a strong-but-imperfect FPNet score sometimes
outranks a merely-good (not perfect) library match under the fixed weights.
**This is exactly the kind of interaction the GBM reranker (stage 7) should
fix** by learning to trust library evidence more when it's strong, and lean
on FPNet more when library evidence is weak/absent — worth checking whether
stage 7's class-1 MRR recovers toward stage-1's 0.908 once the real number is
in.

Fragmentation's lift is modest (+0.014 overall) on its own under weighted
fusion; its value may be more about breaking ties among otherwise-similar
candidates than about being a strong standalone signal — again, something
the reranker (with fragmentation as one of 22 features rather than a single
fixed-weight term) may exploit better than plain weighted fusion can.
