## Part 2 — MolForge de novo generation (Channel 6) — THE MAIN WORK

### Why de novo, why MolForge

Class 3 (fully novel structures, not in any DB) is the only cohort no
retrieval channel can reach, and it's stuck at ~0.017 MRR. De novo generation
is the only path to it — and the intended differentiator vs. the retrieval-
only reference solution. From `docs/03-literature-review.md`, **MolForge**
(Ucak, Ashyrmamatov & Lee, "Reconstruction of lossless molecular
representations from fingerprints", J. Cheminformatics 2023,
doi:10.1186/s13321-023-00693-0) is the strongest reproducible fingerprint→
SMILES decoder: 93.6% exact reconstruction from ECFP4, and the decoder half
of the current MassSpecGym de novo SOTA (MIST+MolForge, 28.27% top-1).

### Architecture implemented (in `src/casmi/models/denovo.py`)

Faithful reproduction of MolForge's stated hyperparameters:
- Encoder-decoder Transformer, **6 encoder + 6 decoder layers**, **8 heads**,
  **d_model=512**, **FFN=2048**, **dropout=0.1**
- **Pre-norm** sub-layers (`norm_first=True`, per the paper's "Annotated
  Transformer" choice)
- **Sinusoidal positional encoding** kept on the fingerprint side (the paper
  ablated this and found +0.2–0.9%, so kept despite attention being
  permutation-invariant)
- Encoder input = sequence of **set-bit indices** in ascending order (the
  paper's "index-order for hashed fingerprints" convention), via a new
  `fingerprint_to_bit_sequence()` helper — NOT a dense projected vector like
  the old GRU version

**One deliberate, documented deviation**: conditions on this project's
existing **10,407-bit** fingerprint (Morgan r2 4096 + Morgan r3 4096 + RDKit
path 2048 + MACCS 167) rather than MolForge's own best ECFP4/2048-bit input.
Reason: FPNet (which supplies this decoder's input at inference) already
predicts that exact layout, and the pool + GBM reranker depend on it too.
Adding a second fingerprint type would force retraining all three for no
benefit MolForge attributes to fingerprint *choice* over *width*.
